## 13. Backend intelligence schema — the actual unlock

**Prompt:** "HAAN BAAKI SAB BHI KARDE" (yes, do the rest too) — full go-ahead on the prioritized plan from #12, starting with the schema extension. Followed by "tune bataya nahi ki kab kya kar sakte hai" (you didn't say WHEN each animation happens) — asked for an explicit phased timeline across all 50 spec items, not just a cost-grouped list.

**Did:** Gave a 5-phase timeline (done / schema-then / report-screen / global-polish / explicitly-skipped, each phase naming which spec item numbers land where) before continuing. Then extended the single per-turn Groq call's JSON contract — no second LLM call, same cost:
- `types.ts`: new `Assessment` (`correctness`/`depth` 1-10, `missingConcepts[]`, `misconception`), `DecisionLabel` union (`DEEPEN`/`CHALLENGE`/`CLARIFY`/`VERIFY_MISCONCEPTION`/`SWITCH_TOPIC`/`CONCLUDE`), both threaded onto `TranscriptTurn.meta` alongside a new `difficulty` (1-5). `Feedback` gained optional `categoryScores` (5 dimensions, 0-100) and `misconceptions[]`.
- `prompts.ts`: the per-turn JSON contract now asks for `decision`/`reasoning`/`assessment` alongside the existing `action`/`reply` — with `decision` explicitly required to pair with a matching `action` (e.g. DEEPEN only with follow_up), and `assessment` required non-null on every turn after the first (explicit instruction against inventing a misconception just to fill the field). Feedback prompt now asks for the 5 category scores + up to 3 real misconceptions.
- `groq.ts`: **strict validation only on the two load-bearing fields** (`action`, `reply` — these drive the guardrail state machine); the new intelligence fields are sanitized leniently (`sanitizeDecision`/`sanitizeAssessment`/`sanitizeCategoryScores`) and simply dropped, never faked, if the model gets them wrong or omits them — a bad `decision` label can never break the interview.
- `route.ts`: difficulty is **derived in code**, not model-reported — `updateDifficulty()` bumps 1-5 from `(correctness+depth)/2` on the real assessment, deliberately not trusting a second independent LLM opinion on its own difficulty. Critically: when the guardrail `resolveAction()` overrides the model's chosen action (the ≥8q/≥4days mechanism from before), the decision/reasoning shown is *also* overridden to an honest "coverage guardrail" note rather than displaying the model's now-inconsistent original reasoning (e.g. model said CONCLUDE, code forced follow_up — showing the model's original reasoning for CONCLUDE would be a lie). The assessment itself is kept either way since it describes what the candidate already said, independent of what the code decides to do about it. Extended the non-contractual GET endpoint with an `evaluations[]` trail (one entry per interviewer turn: assessment/decision/reasoning/difficulty) so the frontend can render Judge Mode and the difficulty indicator without any new calls.

Verified via `tsc --noEmit` + `eslint` only at this stage (clean) — live verification deferred to the end of this batch, once the frontend pieces that consume this data exist too, to use remaining Groq budget efficiently (one combined check instead of one per sub-feature).

## 14. Skip flow, End Early, Cohort Insights, and a second LLM provider

**Prompt:** Several rapid-fire requests in one stretch: (1) let a candidate skip a question they don't know, with a real consequence after 2 skips; (2) a hidden "end interview early" escape hatch for testing, with remaining topics honestly counted as not-covered; (3) a records/leaderboard page showing best-per-category + overall-best across completed interviews; (4) worry about the Groq key running out mid-demo; (5) after being told Groq's real constraint is an 8000 **token-per-minute** cap (tighter than a simple daily request count), a push to actually add Gemini as a second provider rather than just build more mitigations around Groq's limit.

**Did:**
- **Skip**: `skipped: true` on the request (not raw client text — prevents the button being a bypass channel for arbitrary "answers"). Prompt instructs the model to acknowledge it warmly and vary the phrasing, always choose next_topic/conclude (never follow_up on a topic just skipped) — and code force-overrides to next_topic even if the model disobeys. 2nd+ skip applies a **guaranteed** -1 difficulty penalty in code, on top of (not instead of) the model's own low assessment — same "don't just trust the LLM for anything that must be reliable" principle as the coverage guardrails.
- **End Early**: `endEarly: true` bypasses the coverage guardrail on purpose (unlike everything else in this app) — but every unreached topic is counted into `skipCount` and named explicitly to the feedback prompt, so the final scores honestly reflect incompleteness instead of hiding it. Not advertised anywhere in candidate-facing copy; unreachable by the graded contract, which only ever sends `{sessionId, message}`. Verified live on a real in-progress session — feedback correctly flagged the early end and scored unreached categories conservatively.
- **Cohort Insights** (`/records`, `GET /api/interview/records`): lists every interview actually completed on this server (in-memory, honestly labeled as such — resets on restart, same trade-off as session state generally), with per-category leaders + an overall-best callout computed from real `categoryScores`. Explicitly framed as a judge/demo-facing view, not a candidate-facing feature — clarified mid-conversation that the *only* real end-user per the problem statement is the candidate themselves (the AI **is** the interviewer; there's no separate human interviewer role), so a cross-candidate leaderboard is inherently a demo/BI bonus, not core product. Populated with 2 genuinely real completed interviews already sitting in the store from earlier testing (Emily Chen, Noah Kim) rather than fabricated data.
- **Gemini as a second provider**: refactored the ~150 lines of provider-agnostic JSON validation/sanitization/fallback logic out of `groq.ts` into `llm-shared.ts` first (both providers now share one source of truth for "never fake a score, never let a malformed field break the interview"). Read the installed `@google/genai` SDK's actual type definitions directly (not from training memory) to confirm the real `responseMimeType`/`responseSchema`/`systemInstruction`/`Content` shapes before writing `gemini.ts` — same discipline as reading Next.js's docs earlier for the same reason (a freshly-installed package can differ from training-data assumptions). `gemini.ts` mirrors `groq.ts`'s exact exported interface; a new `llm.ts` switchboard (env-gated via `LLM_PROVIDER`, default Groq — the one already proven across dozens of live calls this session) is the only thing `route.ts` imports, so neither provider module needs route.ts to know it exists. Typechecks and lints clean; live verification pending the user adding `GEMINI_API_KEY`.
